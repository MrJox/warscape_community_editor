# The editor shell (`libs/editor`, `app/`)

`wce.exe` is one window with one renderer and one shared scene; tools are modes of it. Phase 4 built the shell, Phase 5 moved the Weather tool onto it
(`tools/weather`, see below), Phase 6 the Tile tool, Phase 7 lets the tools share documents (see Cross-tool composition).

## Pieces

| Piece | File | What it does |
|---|---|---|
| `Command`, `CommandStack` | `editor/command.h` | undo/redo per document; a drag gesture pushes many commands with one merge key and ends as one entry (`break_merge` when the gesture ends); `modified()` follows the saved position |
| `Document` | `editor/document.h` | one thing a tool edits, with its lossless model inside: `publish` into its scene layer, `outline`, `inspect`, `item_transform` / `transform_items` for the gizmo, `save` |
| `DocumentManager` | `editor/document_manager.h` | owns the open documents, one `RenderScene` layer each, re-publishes a document when its stack moved; `unsaved`, `save_one`, `save_all`, layer visibility, the stand-in scene rule |
| `Selection` | `editor/selection.h` | a set of `SourceRef` (document, item); the scene entities that show them come from `RenderScene::entities_of` |
| `Inspector` | `editor/inspector.h` | the documents describe an item through this interface; every property has a `PropertyPath` (document, item, field), the seam the Cinematic editor animates through; `panels.cpp` has the ImGui implementation |
| `CommandRegistry`, `ScriptRunner` | `editor/command_registry.h` | every action is a named command; menus, `--cmd`, `--script` and tests all run the same entries |
| `OrbitCamera`, `FlyCamera` | `editor/camera_controller.h` | viewport cameras on the game's battle lens (FOV 65 degrees, near 1, far 13000) |
| `Viewport` | `editor/editor.h`, `viewport.cpp` | renders the scene into a `RenderTarget`, camera input, click to select (through `Renderer::pick`), the ImGuizmo gizmo (translate/rotate/scale, snap), offscreen `capture` |
| panels | `editor/panels.cpp` | Outliner (per document: tool tag, eye, `*`, context menu, Save all), Inspector, Assets (the VFS tree, filter, only the tool's file types, double-click opens), Log, History (click to jump), Commands (console) |
| `Editor` | `editor/editor.h` | the host window with menu bar, tool switcher and dockspace; owns VFS, renderer, scene, documents, selection, clock; layouts; first run |
| `Tool` | `editor/tool.h` | a mode: opens, panels, menus, viewport input, default layout, commands; `PlaceholderTool` for the future ones |

`libs/editor` is two targets: `wce_editor_core` has no ImGui or GPU code and is what `cli/editor_check` tests; `wce_editor` is the UI.

## Tools

Registered by `app/main.cpp` through `tools/tool_factories.h`: Weather (Phase 5), Tile, Unit, VFX, Terrain, Cinematic (placeholders with a
panel that says what is planned). **Ctrl+1..9** switch tools.

To add a tool: derive from `Tool`, give it an id and title, return the file extensions it opens, implement `open` (return a `Document`), add panels in
`draw_panels`, commands in `register_commands`; add a factory to `tool_factories.h` and register it in `main.cpp`.

## Weather tool (`tools/weather`)

Opens `.environment`, `.lighting` and `.xml` (weather definitions, vfx) from the packs or from disk (File > Open file, `--open`, `--open-disk`, double-click in Files). Each file is an
`XmlFileDocument` around the lossless `XmlDoc`: attribute edits are `XmlAttrCommand`s (merge per drag gesture), structural edits (duplicate, delete, move, add child or attribute,
remove attribute) are snapshot commands. Save writes a loose file under the output folder (File > Set output folder, `output_dir`; the game's `data` folder is never touched), re-reads it as
the new baseline and clears the history, so the saved bytes differ from the pack file in the edited spans only.

| Old weather_editor feature (`docs/plans/weather_current_state.md`) | Where it is now |
|---|---|
| Files browser with filter and categories | **Files** panel (and the shared Assets panel, filtered to the tool's types) |
| Properties tree with typed editors, search, per-attribute revert, add / remove | **Properties** panel (tree) and the shared **Inspector** (typed editors for bool, int, float, colour, variance, euler, string) |
| Structural edits with snapshot undo | context menu in Properties; `xml_op`; Ctrl+Z / Ctrl+Y, History panel |
| Changes tab | **Changes** tab of Properties (every modified attribute of the file, revert) |
| Live preview on the sample map, orbit camera, battle lens | shared viewport; the active environment document lights `RenderScene::environment` every frame (a default dry environment when none is open) |
| Cross-fade between two environments | **Weather scene** bar and `blend <t>` |
| View modes (HDR, albedo, normal, depth, ...) | **Weather scene** bar and `view <n>` |
| Sample map seed and count, re-roll | **Weather scene** bar, `sample`, `reroll` |
| Graphics options (gamma, brightness, SSAO, DOF, shadows, vignette, flare) | **Settings** menu (read from `preferences.script.txt`) |
| Weather selection database: Pick and Edit tabs, `.xml` and `.bin` | **Selection > Weather picker** (`WeatherPicker`, `VariationEditor`), `picker`, `pick k=v`, `vdb-script` |
| CLI `--open`, `--open-disk`, `--cam`, `--frames`, `--shot`, `--capture`, `--view`, `--blend`, `--pick`, `--picker`, `--vdb-script`, `--no-flare` | same flags of `wce.exe`; the weather ones are commands of the tool (`--name args` runs the command `name`) |

Differences: the legacy app held one active file; here every open file is a document, and the one that lights the scene is the last active `.environment` / `.lighting`. `weather_editor.exe` was removed in Phase 8; the render regression is the `wce.exe` captures (`scripts/shots.sh`). `scripts/weather_check.sh` supersedes `variation_e2e.ps1`.

## Tile tool (`tools/tile`)

A tile's root is its tile database entry (`_tile_database/TILES/*.xml`, [formats/tile_database.md](formats/tile_database.md)): it names the folder of `tile.ted` (location + variation) and holds the size, colour, ground groups, height / normal parameters and links. Open one with the **Tiles** panel (the kits' entries from an index, no scan; word filter; double-click opens the first variation, a button per variation; above the list, **Favourites** (the star at a row's right, `tile_favourite <key>`) and **Recently opened** (the last 10 tiles opened, with the variation, which a double-click opens again), both of the panel's source and under the same kind and word filters, kept in `[tools.tile] favourites` / `recent` (`tile_marks` logs them); an exported tile opened into a workspace counts as the packs'), Tile > Open tile... (an entry `.xml`, a `tile.ted`), `--tile <target>` or the `tile <target> [variation]` command, where the target is an entry file, a name (`assembly_kit/osgiliath_test`, or the entry's file name), a variation folder, a tile folder (opens its first variation) or a `tile.ted`. A folder or `tile.ted` resolves its entry from the path; outside a kit there is none and the tile opens with a warning and no height scale. The **Tile** panel shows the entry read-only (colour, size, flags, ground groups, a variation chooser that opens the other variation as its own document, the variations' height / normal / overlap values, links and targets). A `TileDocument` wraps a `TileProject` (the lossless `TedScene` and the `HeightField`), and everything it does is a `Command` on the document's stack:
attribute edits on the scene (moves, rotations, polygon points) merge per gesture, structural edits (duplicate, delete, add building, polygons, layers) keep whole-document snapshots, and a brush stroke is one entry however many steps it took. Items are element indices + 1 (item 0 is the terrain), so the shared
outliner, selection, inspector, gizmo and history work on them.

**Problems** (`wce_tile::vegetation::trees_outside_exclusions`): BOB keeps a manual `VEGETATION_INSTANCE` only when it stands inside a `VegetationExclusionPolygonInstance` (none when the tile has no such polygon), so the others never reach the game. They are listed in the Tile panel's *Problems* (a click selects and frames one; `tile_problems` logs them), an error in the log when the tile opens, and a warning at the front of every save's message.

**Where tiles are saved** (`wce_tile::project_files`, `tile_document/kit.rs`): a tile is saved as **`tile.wce`** in the game's projects folder (`<projects>/assembly_kit`, laid out like a kit's `raw_data`: the tile at `raw_data/terrain/tiles/...` and its entry in `_tile_database/TILES`), never in the Assembly Kit. `tile.wce` is a superset of `tile.ted`: the same XML, the root `<project>` marked `wce_version="1"`, where the editor may keep what TEd does not know, named so that the conversion finds it: an attribute `wce_...`, an element `Wce...`. Numbers are kept at full precision (`format_number`: positions, orientations, points, handles, areas); TEd's precision is applied only by the conversion (`ted_number_text`: `%.6f` of the float32 trimmed, `%g` for points, handles and `lf_offset`, integers as they are, only where that is shorter, so what TEd wrote stays byte for byte: 2 of the kit's 39.9 million values would differ, `examples/ted_numbers_check.rs`). A placed prefab is a **reference**: an instance group with `wce_prefab="<key>"`, kept in tile.wce without its contents; the editor fills them in from the prefab when it opens the tile (`expand_prefabs`, prefabs placed in prefabs too) and leaves them out when it saves (`strip_prefab_contents`), so an edit of the prefab reaches every tile that places it. The conversion for TEd (and for the game export, which compiles the editor's scene) writes the group with its contents: TEd's copy. The first save of a tile opened from the kit makes its project (the tile's folder and its entry copied, `tile.wce` written) and the document goes on from there; opening a kit's tile that has a project opens the project. Save writes only what changed (the edited spans, the kit-exact PNG encoder for the height map, the river files of rivers that changed); `save_to <folder>` writes the tile elsewhere. **Tile > Save for Assembly Kit** (`save_for_kit [raw_data]`) writes a tile TEd reads into the kit that has the tile's kind: `tile.ted` (`project_files::to_ted`: the polyfills of the editor's features, then what TEd lacks dropped, all in the log), every river file, the height map, the other files and the entry; files with other bytes keep a `.bak`, identical ones are left alone. **Tile > Import from Assembly Kit** (`import_from_kit`) opens the kit's copy of the project, whose next save replaces the project. A tile **extracted** from the packs (`open_exported`) is decompiled into the projects with `_extracted` at the end of its tile's folder and its entry's location (`.../farm_western/1x1_extracted/aa`), so that it never takes a kit tile's place; Save for Assembly Kit and the export to the game (`save_exported`, which reads `tile.wce` as `tile.ted`) take the mark off.

What it shows: the terrain from the height map (patches of the shared terrain pass), BUILDING_INSTANCEs as their real models (`rigidmodels/buildings/<key>/` pieces; a key without a drawable model is a wire box and is listed in the log), every other instance as a small marker batched per type
with distance culling (vegetation 450 m, decals 300 m, others 3000 m, adjustable in the Tile menu), polygon outlines, the tile's rectangle, and highlights for the selection (box, axes, polygon point handles) and the brush ring. Where the height map sits is in `docs/formats/tile_ted.md`.

**Scene panel** (Phase 1, the layer tree laid out like TEd's Scene tab): a name, then at the right edge the **type's icon** (`entity_types.rs`; the types and what the editor does with each are in [tile_entity_types.md](tile_entity_types.md)), **where it is exported** (the export type of the nearest layer above that is not Normal, dimmed when inherited, red when Don't Export; a click on a layer's sets it), an **eye** (`OIF_VISIBLE`) and a **cursor arrow** (`OIF_ACTIVE`, selectable), greyed when off (dimmer when only a layer above is off). The name filter keeps what matches with everything below it (closed as it was left) and opens the layers above it. Opening a tile brings the Scene tree to the front. Beside the name filter, the **types' filter** (a funnel, gold with the count while some types are hidden) opens the types on the tile with their icons and counts (right click: that type alone, again: all; All / None; `tile_type`): a type turned off is neither listed nor shown (a view setting of this tool, not a flag of the file). A hidden layer hides everything below it (models, markers, polygon outlines; it is still exported); a locked one cannot be picked with the mouse or moved with the gizmo. Click selects (Ctrl toggles, Shift extends), double-click or F2 renames (Esc cancels), Del deletes (a confirmation above 200 elements), Ctrl+G groups the selection into a new instance group (`UserInstanceGroup`, TEd's group, at the centre of the items, which keep their place in the world) in the **working layer**, Ctrl+U takes the selected instance groups apart into the working layer (groups only, not layers), *Group into a new layer* is in the right-click menu, drag and drop moves into a layer (middle of a row) or in front of / behind a row (top / bottom quarter) keeping the world positions, the right-click menu has New layer inside, Group, Move selection here, Rename, Duplicate, Delete, Hide / Show, Lock / Unlock and Export (TEd's Export, Don't Export, Export Separately, Escalation 1..3; also a combo in the Inspector). Every action is one undo entry (text splices); open layers are remembered by their name path. The **working layer** (TEd's): a layer set with *Set as the working layer* (right click; `tile_working_layer`), marked with a pen and shown above the tree, takes every new item: placed buildings, drawn polygons, groups and ungrouped items; without one they go to the root. It is kept by its name path for the session (a rename keeps it; a move or a delete clears it). The **Create** panel (`create_panel.rs`) lists everything that can be put in a tile, in the working layer: buildings, trees, decals, models and effects (every valid key, `TileDocument::key_catalogue`, read once per tile from the game's files: building keys from the kit's `battlefield_buildings` and the building model folders, trees `species.variant`, decal models as TEd writes them, models, effects `vfx/*.xml`; `keys <type> [filter]` lists them), lights, prefabs, the gameplay markers and areas, the AI regions and hints, the siege's types (Siege AI nodes, edges and polygons, procedural walls), rivers and roads, by category, with favourites (the star) and the recent ones, searched by words over all of them. **Shift+A** over the viewport opens the same search at the mouse (Enter takes the first; `quick_add`). A click on an entry starts making it: a placed type with clicks on the terrain (R / Shift+R turn it by the rotate step, Esc stops), a drawn one with clicks (Enter finishes). While placing, what a click places is **previewed under the mouse** (`TileDocument::set_preview`: the models, decals and effects of the text that will be inserted, markers and polygon outlines on the ground; not pickable, not in the document), and the **Inspector** shows it as "New <type>" (`TileDocument::inspect_draft`: TEd's Property Editor rows with the kit's defaults and its rules, and the turn); its values go into every copy and are kept per type until *Reset to the defaults* (`Draft`). The preview and a click insert the same text (`draft_text`, `place_text`). `create <type> <x> <z> [key]`, `add_polygon`, `draw_polygon <type> [hint]`, `place_preview <type | building | prefab> <x> <z> [key]` from scripts. While placing or grabbing, **placement chips** at the top right of the viewport (`placement_modes.rs`, kept in the Tile settings; `place_modes`) say what it stands on — *Freeform* and *Landscape: Above* (TEd's, on the terrain under the mouse) or *Entity: Above* (on whatever is under the mouse: the pick pass also writes each pixel's world position, `Renderer::pick_surface`, and the item itself is left out while grabbing; kept as freeform at that height with `wce_surface="entity"`; it does not follow the thing below) — and how it is turned: upright, or *Follow surface* (tilted so that its up is the surface's normal, the terrain's or the thing's, the R turn kept; `wce_rotation="surface"`). TEd gets both as what they are (freeform at the height, the tilted orientation): the polyfills only drop the marks. Per item, the Inspector's **surface_mode** has the three (Entity: Above marks the item and keeps its height; G then puts it on what is under the mouse) and its **rotation** is *Free* (as given, the default) or *Follow surface* (tilted to the terrain under it now, its heading kept, `TileDocument::tilt_to_surface`; a grab tilts it again to what it is moved onto). `start_making <type | building | prefab> [key]` starts placing from a script as the Create panel does. While a tree is placed, a chip beside them switches to the **vegetation brush** (`veg_brush.rs`; settings in the Inspector and the Tile settings; `veg_brush on|off [radius] [spacing] [clearance] [fill]`): a drag paints trees of the chosen key into the working layer, loose, one undo entry per stroke (previewed while it lasts); a dab tries points at random in the circle (as many as `fill` of the room the spacing leaves) and keeps one at least `spacing` from every tree (the tile's and the stroke's) and `clearance` from the other things' footprints (their models' bounds, `TileDocument::footprints`), each at a random scale (`scale from`..`to`) and turn, and with *Follow surface* tilted to what it stands on at its own point (`veg_paint <x z>...` paints a stroke from a script); with *Entity: Above* each tree stands on whatever is topmost at its point (a building, a rock; the terrain where nothing is; trees left out), found by a straight-down id pass over the circle (`Renderer::surfaces_below`, about 10 cm a pixel, the LODs the camera sees, so it does not depend on the view), and the things' clearance does not count for the trees that stand on them; Ctrl + drag takes the manual trees in the circle away (red crosses until the stroke ends; one undo entry). **Vegetation sets** (`wce_tile::vegetation_sets`, `veg_sets.rs`): named lists of tree keys, each with a weight and optionally its own scale range, as `<name>.wce` in the projects' `raw_data/art/vegetation_sets` (`<VEGETATION_SET wce_version="1">` of `<entry key weight [scale_min scale_max]/>`); at the top of the Create panel's Vegetation (`veg_set <name>`), they place or paint their trees, a key picked by the weights for each (and its scale range in the brush). *New vegetation set from the selected trees* (the Create panel and the right-click menu; `veg_set_new <name>`) weighs each kind by how many are selected; while a set is in use, the Inspector edits it in its own framed box (one row per tree: weight, its own scale range or the brush's, remove), saved at once; while the brush paints, its settings are at the top and the tree's draft is not shown (the brush picks keys, scales and turns). A set can also be made from scratch: **Ctrl + click** (or **Ctrl + Enter** in the search, which then keeps the keyboard; Enter alone takes the first entry found) on a tree (or a set) in the Create panel adds it to a new set (not saved; `veg_set_add <key>...`; in the Shift+A popup too, which stays open to add more) and places or paints with it from the first tree on, shown at the top of the Inspector (placing or not), where its trees are edited, it is named and saved (`veg_set_save <name>`; placing goes on with the saved set), used to place or paint at once, or discarded (which stops placing with it). Quitting with a new set not saved asks first (`Tool::unsaved_work`: work a tool holds that no document saves is listed in the quit prompt as lost). What is placed or painted points to the set (`SetInUse`) and reads it for every tree, so edits apply at once. **Splines** (rivers, `SplineRiverInstance`, and roads, `SEGMENTED_SPLINE_INSTANCE`; `wce_tile::splines`) are drawn the same way, laid out as TEd does (the instance at the first point, handles a third of a segment along the line through the neighbours, at the point's height, the ends' unused handles `0,0,0`), drawn as their Bezier curves. A selected spline shows its points and blue handles: a point drags with its handles, a handle drags at its point's height with the other one mirrored, shift+click inserts a point (beyond an end the spline grows there), `Del` removes one (2 stay); the Tile panel edits the selected point's values (width, foam, alpha fade, flow speed, terrain offset; *all points* for every one), one undo entry per drag. `polygon_point move|insert|remove|in|out|prepend`, `spline_value <attribute> <value> [index|all]`. A save writes `river_spline<n>.xml` for each river that changed ([docs/re/water.md](re/water.md)); roads are not exported (a TEd painting guide). **Prefabs** (`prefab_panel.rs`, `wce_tile::prefabs`): TEd's saved groups, `<kit raw_data>/art/prefabs/**.xml` (an `INSTANCE_SELECTION` holding one `UserInstanceGroup`) of the kits the Tiles panel lists and of the tile's kit, after the Tile settings' **prefab folders** (a collection kept elsewhere, like a checkout of a prefab repository; new prefabs go into the first one; the panel's *Add a prefab folder...* adds one). The library is read again for another tile and after the settings change. A reference to a prefab (`wce_prefab`) is a copy of it: a *Prefab* row in the tree, which opens like a group (a click on one of its items there opens the copy for overrides); in the viewport a click on its contents selects the copy. A selected group, layer or copy is outlined (and framed, F) by the items below it (`Document::outline_items`, `Editor::selection_entities`). The copies stay in tile.ted as TEd's groups (linked copies, not references: the memory a copy takes is its text, as before). Prefabs are placed from the Create panel (`prefab_place` places one at a point or the view's centre) as references (above). The editor's prefabs are `<key>.wce` in the projects' `raw_data/art/prefabs` (a superset of TEd's file, its root marked, references inside kept without contents); a `.wce` takes the place of the kit's `.xml` of the same key. An edit (*Apply the prefab edit*) is saved there, never in the kit (the first time, a `.wce` is made from the kit's file); *Save prefab for Assembly Kit* (`prefab_save_kit <key>`) writes TEd's `.xml` into the kit's `art/prefabs`, the prefabs in it baked. A group only named after a prefab is a plain group (it becomes a reference when its contents are the prefab's, below). **Copies into references** (`wce_tile::prefab_refs`): an instance group named after a prefab (its key, case aside) whose contents are exactly that prefab's (every element, attribute and value, positions within 0.1 across, `prefab_refs::POSITION_TOLERANCE`, the drift of TEd's copies, and polygons' `area` left out, the flat area of their points that follows that drift; whatever the group's own place and turn; the height of what stands on the terrain, Landscape: Above items and such a polygon's points, is not compared: it is the terrain's wherever a copy is, so a reference gets its prefab's and keeps no override of it) becomes a reference to it when a tile opens from the Assembly Kit (outermost copies first; it opens unmodified), and again with *Turn copies of prefabs into references* in the Tile panel's Prefabs (`prefab_recognise`, one undo entry); groups named after a prefab that differ from it stay plain groups (counted in the log). **Overrides**: what a reference's items differ by from its prefab's, values only. A click on an item of a selected copy **opens** it (`opened_copy`: its items are listed in the Scene tree and selected; it closes when the selection leaves it), and what is edited there is an override, found when the tile is saved and kept in tile.wce as `<WceOverrides><WceOverride path element attr value/></WceOverrides>` after the reference's empty `children` (`path`: the element indices down from the contents' top); filling the reference in applies them (one that no longer fits its prefab is left out, logged), *Save for Assembly Kit* bakes them, and *Apply the prefab edit* keeps the other references' overrides on top of the new contents. The Inspector marks an overridden value's label in the warning colour (its tooltip: the prefab's value; `Inspector::mark_fields`) with *Revert to the prefab's values*, and a reference shows how many it has (*Revert all overrides*); both buttons are always there, greyed out when there is nothing to revert. In the Scene tree an item that overrides is in the warning colour, marked *(override)*, and the reference and the groups in it show how many of their items do. Adding, taking away, moving or grouping items inside a reference is refused (`TileDocument::check_structure`; Edit prefab or Unpack prefab for that); a reference whose items still differ by more keeps its own contents in tile.wce. On a copy, *Edit prefab* lists its contents for editing; *Apply the prefab edit* writes the prefab file at once (only its group's contents change) and gives every other copy in this tile the new contents (one undo entry; other tiles are not touched); *Cancel* gives the copy the file's contents back; *Unpack prefab* renames it `<key> (unpacked)` and drops its reference: a plain group with the contents it has. *Save as prefab...* on an instance group writes it as `<projects>/assembly_kit/raw_data/art/prefabs/<folder>/<name>.wce` and makes the group a reference to it. Commands `prefab_list`, `prefab_rescan`, `prefab_place`, `prefab_edit`, `prefab_apply`, `prefab_cancel`, `prefab_unpack`, `prefab_save`. The Inspector shows visible / selectable check boxes for layers and instances and **position (world, m)** (TEd's X / Y / Z fields). The gizmo works with the mouse (ImGuizmo's `CanActivate` is told the viewport's button may be the hovered item), handles are 60 % larger, and while a gizmo is shown a left drag that misses it does not orbit (Alt + left or the right button do).

Layer commands: `tile_flag`, `tile_new_layer`, `tile_rename`, `tile_move_to <what> <layer> [before <x>]`, `tile_group`, `tile_delete`, `tile_duplicate_layer`, `tile_export_type`, `tile_select_layer`, `tile_select_in <layer> <type> [frame|click]`, `tile_tree`; tests `assert_flag`, `assert_shown`, `assert_selectable`, `assert_layer <path> children|exists|export|child ...`, `assert_selection_names`, `assert_cam_same` / `assert_cam_moved` (after `cam_mark`), `gizmo_drag`. A layer is named by its path from the scene graph (`Walls/Standard_Walls`), `#n` is an element index, `selected` the selection.

**Placement** (Phase 2; the rules were measured in TEd, `docs/formats/tile_ted.md`): an instance is *Landscape* (`surface_mode="MSM_LANDSCAPE"`, TEd's `Landscape: Above`) or *Freeform*. A landscape instance stands on the terrain: moving it in x / z (gizmo, G grab, the Inspector's world position, `tile_move`) puts it on the terrain at the new place, and a y that is dragged or typed is ignored (the y handle does nothing, as TEd refuses a typed y); a freeform one has any y. Landscape -> Freeform keeps y, Freeform -> Landscape snaps. **A height stroke carries the landscape instances under the brush with the terrain** (their y changes by the change of the height under each; the same undo entry as the stroke, so undo puts both back; hidden and locked ones follow too; freeform ones stay). `lf_offset` is not used: it is 0 in every tile TEd wrote and equals the y in the older CA tiles. The **Inspector** has TEd's `placement` combo (Landscape: Above / Freeform) for instances and says how far a landscape instance is from the terrain; the **Tile panel** has a *Placement* section (counts, Landscape / Freeform / Snap to terrain for the selection, layers included, and *Report off-terrain* with a tolerance: a list of the landscape instances that are further off, *Select them*, *Snap them*), a combo next to *Add* for the placement of new buildings (default Landscape), and *Drop to terrain* snaps the selection whatever its mode. Duplicating a landscape instance puts the copy on the terrain. Commands: `tile_placement <what> landscape|freeform`, `tile_snap <what | all> [freeform]`, `tile_set_world <x> <y> <z>`, `tile_report_off_terrain [tolerance] [layer]`; tests `assert_placement`, `assert_on_terrain <what> 0|1 [tol]`, `assert_off_terrain_count <tol> <n>`, `assert_placement_counts <landscape> <freeform>`.

**Ground** (Phase 3): the terrain is drawn by the game's own terrain shaders (`docs/re/terrain.md`, "The tool's terrain pass"): the tile's blend / index maps (from `blend_map.tif`), a normal map from the live heights and the textures of a climate. The Tile panel's *Ground* section has the *blended ground* check box, the *climate* (the kit's `_settings.xml` list; default ROME_Continental: the tile does not store its climate), the *season* and a *view* combo (colour, blend groups, ground types, protection: TEd's debug views of the tile's maps, drawn as flat images) and says what is shown or why the plain tiled texture is used (no blend map, no database entry, no textures). Changing climate or season rebuilds the texture arrays. Commands: `tile_terrain blended|flat [climate] [season]`, `tile_ground_view colour|groups|ground|protection`; test `assert_ground blended|flat [textures n] [climate]`.

**Water** (Phase 4): river ribbons from the `SplineRiverInstance` elements and a sea / lake plane for the sea, coast, lake and river-mouth tile sets, drawn by the renderer's water pass with the game's own shaders (`docs/re/water.md`: `rigidriver`, `waterplane` and `waterrefraction`: refraction of the lit scene, environment reflection, sun glint, fog); the Tile panel's *Ground* section has the *water* check box and says what was found. Rivers are drawn whatever the spline layer's eye says (TEd does too). Commands: `tile_water on|off`; tests `assert_water <n>`.

**Procedural trees**: the trees BOB generated for the tile (`<list>.tree_list.bin` of the packed tile, one per climate key plus `default`), drawn with the static `VEGETATION_INSTANCE`s, not selectable; the list trees standing where a shown static instance stands are skipped. Chosen on the Tile panel's *Ground* section (*procedural trees*, default `default`) or with `tree_list [name | gen:name | none]` (no name: log the lists). `gen:<list>` (and any list a raw tile has no packed file for) is generated as BOB would (`wce_tile::vegetation`) from the tile as it is: its seeds, edited height map, exclusion polygons, the *saved* `blend_map.tif` and the Assembly Kit's vegetation parameters; generated lists are the whole list BOB writes, the static trees included (they shift the yaws of the generated trees sharing their model). *regenerate* (or the command again) generates it anew after an edit. Generation runs on the UI thread: 0.01–0.1 s for most tiles, about 2 s for the largest (custom_mont_blanc, 51k trees). Placement as the game's (`docs/re/vegetation.md`): terrain height unless freeform, scale byte / 127, the game's random yaw for one worker, tilted to the terrain (static trees too). The static instances draw the model their key becomes on the shown list's climate (`per_climate_tree_conversions.xml`: olives turn to oaks on ROME_Atlantic...), as the game's lists have them. Trees (and grass) draw their season's diffuse (`<name>_<season>_diffuse`, the ground's season) where the game has one.

**Grass**: BOB's `default.grass_list.bin` (packed tile or the tile's folder) drawn by the renderer's grass pass with the game's rigidgrass shaders, within 100 m of the camera (where the game's vertex shader has sunk it into the ground); models from the climate's `terrain/vegetation/battle/grass/<climate>/` folder, else `default`. Placement as the game's: on the terrain, tilted to its normal measured over the patch's size, patches on slopes over 0.7 rad left out, the game's random yaw for one worker; the season's diffuse (`<name>_<season>_diffuse`) where the climate has one; grass casts shadows. A raw tile without a packed list (or with *generated* ticked on the Tile panel's *Ground* section, `grass generated`) gets BOB's grass generated from `<Grass generation_seed>`, the saved blend map and the kit's `max_grass.xml` (exact to BOB on 119 of 125 kit tiles); *regenerate* / the command again after an edit. `grass on|off|generated|packed`.

**Tile links** (Phase 6a, read-only; `docs/re/tile_links.md`): the Tile panel's *Tile links* section lists the entry's link targets and rules and *show on the ground* draws the cells they name coloured by link set. Commands: `tile_links [on|off]` (no argument: log them); tests `assert_links <targets> <rules> [drawn 0|1]`, `assert_link_cell <x> <y> <x0 m> <z0 m>`.

Entry commands: `tiles [words]` (the browser's rows), `tile_entry` (log the entry), `assert_entry <field> <value>`, `assert_tiles <n> [words]`; test helpers `gizmo_drag <x|y|z> <pixels>` and `cam_info`. Extra commands: `tile_mode`, `brush`, `grab_to x z`, `tile_click`, `tile_click_ground`, `tile_drag_point`, `draw_polygon`, `tile_diagnostics` and the tests `assert_instances`, `assert_type_count`, `assert_world`, `assert_world_xz`, `assert_height`, `mark_height` / `assert_height_delta`, `assert_selected_type`,
`assert_at_cursor`, `assert_mode`, `assert_grabbing`, `assert_file_exists`. `mouse move|click|drag|wheel|off x y` (pixels or `50%` of the viewport image) drives the same ImGui events as the real mouse; in fixed-step runs the real mouse is ignored. `where [x y | on | off]` prints the camera's, its orbit target's and the cursor's coordinates (scene and game units; in a map context
also the map cell, and the cursor's height above the sea), `x y` probing the ground under that pixel; the same readout sits in the viewport's
bottom-left corner (View > Coordinates). View > Fog turns the distance fog off (the fog pass and the rivers' own fog), as `gfx fog off`.

`tile_studio.exe` (and its own renderer) was removed in Phase 8; the tile captures of `scripts/shots.sh` are the render regression.

## Cross-tool composition (Phase 7)

Every open file is a `Document` in the one `DocumentManager`, whichever tool opened it: a tile and an `.environment` (and vfx files) are open at once, each with its own history, modified marker and layer. Opening a file of another tool
switches to that tool (`open_path(..., switch_tool = false)` does not); `activate <id|kind|title>` and a click on a document in the Outliner choose which one the menus, History and `save` act on; a double-click there (or *Edit in its tool*) switches to its tool.

| What | How |
|---|---|

While a document of the same file is open (the Weather tool's), the scene is lit by that document instead (`Document::environment`), live while it is edited (`Editor::update_lighting`, after the tool's `update`); closing it goes back to the file of the packs. ## Layouts

ImGui runs with docking and no ini file. Each tool has its own layout file `<config folder>/layouts/<tool id>.ini` (see the folders below). Switching tools saves the leaving tool's layout and loads the entering one's; without a file the tool's `default_layout`
(DockBuilder calls; the base class builds the standard one: outliner left, inspector right, assets/log/history below, viewport in the centre) is built. `layout save`,
`layout reset`, File menu entries and saving on exit (not in batch runs) manage the files. A layout that was never loaded (a switch before the first
frame) is not saved over the tool's file.

A plain interactive start opens the tool the last interactive session was in (`last_tool` in the settings, kept on every switch,
`Editor::restore_last_tool`). `--tool <id>` starts in that tool instead and leaves `last_tool` alone, and so does any scripted run (`--script`,
`--cmd`, `--open`, `--tile`, `--shot`, `--capture`), so that scripts start where they expect.

## Settings and first run

`wce_foundation::settings`. The editor keeps its files in the system's folders for an app called `wce`:

|---|---|---|---|
| config (`settings.toml`, `layouts/`) | `~/.config/wce` | `%LOCALAPPDATA%\wce\config` | `~/Library/Application Support/wce` |
| data, the user's files (`projects/<game>/`) | `~/.local/share/wce` | `%LOCALAPPDATA%\wce\data` | `~/Library/Application Support/wce` |
| cache (`map_context/`, `tile_index/`) | `~/.cache/wce` | `%LOCALAPPDATA%\wce\cache` | `~/Library/Caches/wce` |

the tool reads and writes with its own serde type (`Editor::tool_settings`, `Editor::update_tool_settings`), so the shell knows nothing of it. Saves write a temporary
file and rename it over the old one. A file that does not read is kept as `settings.toml.bad` and the defaults are used. An environment variable wins over the
file and is never written back:

| Setting | Environment |
|---|---|
| the game folder | `WCE_GAME` |
| mod packs | `WCE_MOD_PACKS` (`;` separated) |
| loose folders | `WCE_OVERLAY` (`;` separated) |

### Appearance

`theme.rs`: the UI font is Inter with Lucide's icons merged in (`icons.rs` names them; the private use area is taken out of Inter, which has glyphs
of its own there), and Dear ImGui's vector font is the monospace one (the log). Themes: `dark` (the default: neutral greys, one blue accent, soft
corners), `light`, and `imgui` (Dear ImGui's own dark style); `[appearance] theme` and `font_size` pick them. The style is built again between frames
when the appearance changes, so the Settings window shows a change at once. Panels take the colours with a meaning (error, warning, modified,
success, highlight, the dim text) from `theme` instead of fixed values, so that every theme keeps them readable; what is drawn over the 3D view keeps
its own colours. Appearance > "Dear ImGui's style editor" edits the live style, to work on a theme.

When the game folder is not set or does not exist the editor starts without the game and shows the first-run dialog: it fills in the Steam library's Attila
folder (registry `SteamPath` + `libraryfolders.vdf`), lets you browse, and **Save and continue** (command `setup`) writes the settings, mounts and starts the
active tool.

`frame_cap` (View > Frame rate cap, command `frame_cap`, environment `WCE_FRAME_CAP`; default 60, 0 = none) holds an interactive session to that many frames per
second: rendering the scene as fast as a fast laptop display refreshes kept the GPU at 100 % until it throttled itself (to 180 MHz of 3090 on the RTX 5070 Ti
laptop, 10x slower frames). Shots, captures and frames while a script runs are not capped (perf measurements stay the real cost of a frame).

## Command line

```
wce.exe [--tool <id>] [--open <path> | --open-disk <file>] [--cam yaw pitch dist [target_y]] [--cmd "<command>"]... [--script <file>]
        [--frames N] [--shot <file.png>] [--capture WxH <file.png>] [--fixed-step <seconds>] [--live] [--background | --foreground]
```

`--shot`, `--capture` and `--script` runs are unattended: their window is created non-activating, kept out of the taskbar and Alt-Tab and put behind the other windows, so a test run never takes the focus from a game or an editor in use. `--foreground` (or `WCE_FOREGROUND=1`) brings back
the normal window, `--background` (`WCE_FOREGROUND=0`) makes an interactive run quiet too.

Everything becomes a script: `--tool` and `--open` first, then `--cmd` / `--script` in order, then `frames N` + `shot` (the whole window after N rendered frames) or
`capture` (the scene offscreen, no window involved), then `quit`. Shots, captures and scripts run on the fixed-step clock (1/60 s per rendered frame), so the same
script gives the same pixels. Exit code 1 when a script line fails.

Script format: one command per line, `#` comments, double quotes group, a leading `-` lets a line fail, `frames N` waits N rendered frames. `help` in the Commands panel (or as a command)
lists them all. Test commands (`assert_*`) fail the script when they do not hold; `key Ctrl+2`, `click_item 13`, `move 3 5 0 2` drive the same code paths as the keyboard,
mouse and gizmo.

## Gizmo and ImGuizmo

ImGuizmo wants row-vector matrices (v * M, row-major); the engine's are column-vector (M * v), so the viewport passes transposes (`to_gizmo` / `from_gizmo` in `viewport.cpp`). The gizmo moves the
first selected item's pivot (`Document::item_transform`); the change since the last frame, `new * inverse(old)`, goes to `Document::transform_items` for every selected item with a gesture id,
so a whole drag is one undo entry. Scale is accepted by the gizmo but a document may ignore it (the sample map does).

## Selection outline

The selection is drawn as an outline around its silhouette (`Renderer::pass_selection_outline`, an editor pass like picking, not a game
shader): the selected meshes and terrain (through the draw sets, as the id pass draws them) and the selected overlays go into a mask at the
viewport's size, once whole and once against the scene's depth; a full-screen pass colours the pixels within `selection_outline_px` of the mask,
solid next to the visible parts and faint (35 %) next to the hidden ones. Colour and width come from the editor (`Editor::selection_outline_style`:
the theme's highlight, 2 px times the display's scale; 2 px in scripted runs). An item without a mesh of its own is outlined from an overlay
that is drawn only into the mask (`Overlay::selection_mask`): the Tile document puts the selected markers' shapes there (`set_highlight`),
and keeps only a selected polygon's point handles in its visible highlight. A selected light keeps its reach box. With 672 wall pieces of the
Ravenna tile selected a frame takes about 0.3 ms more (it took 7.6 ms more when the selection's entities were looked up item by item).

- `tile_check.sh` also runs `scripts/tile_terrain.txt` twice on `tdd_custom_lothlorien/1x1/aa` (blended ground with 12 layers, another climate and season, flat, back to blended, a height stroke that leaves the ground alone, the three debug views): every capture is identical between the two runs, blended again equals the first capture, the other looks differ from it. `terrain_check` (a fast gate of `gates.sh`) tests the DXT decoder on hand-made blocks, the kit's climates and the texture path fallbacks, and bakes the tile against the real packs (all layers found, 4 texels per metre, not flat, two bakes byte-identical, another climate gives another image, an unknown climate falls back to `default`).
- `tile_check.sh` also runs `scripts/tile_placement.txt` on the CA tile `terrain_rugged_hills_desert/1x1/aa` (5 landscape and 2 freeform instances: typed x / z and y, mode switches, batch and snap-all, a stroke that carries the landscape instances, a duplicate; all undone and saved equals the original `tile.ted` and height map byte for byte). `placement_check` (the oracle: our world matrix against TEd's `building_list.xml`, 73 tiles) is a gate of `gates.sh` since Phase 0b.
- `tile_check.sh` also runs `scripts/tile_gizmo.txt` (a drag on each axis moves the building, one undo entry per drag, the camera does not move; a drag that misses does not orbit while a gizmo is shown), `scripts/tile_layers.txt` (flags, hide and lock against picking with the mouse, every structure command with undo and redo, moving keeps world positions, undo all and save equals the original `tile.ted` on the 55 MB osgiliath_test) and `scripts/tile_scene_ui.txt` (the Scene panel with the scripted mouse: eye, cursor arrow, drag and drop, F2, Del).
- `scripts/cross_tool_check.sh` (render, `cross_tool_check` in `gates.sh`): see Cross-tool composition. `editor_check` also covers the document manager's unsaved list, `save_one` and the stand-in scene rule.
- `perf_check` (fast, no window): thread pool, frustum / LOD / size culling of the draw set, the DDS mip stream plan, the tile document's element index against the plain transform walk on three tiles (77 633 instances on the biggest), the pick grid against a brute-force ray test. `xml_splice_check` (fast): the in-place structural edits of `XmlDoc` against the functional ones, undo and redo of their records exact.
- `scripts/shots.sh`: the weather shots (legacy app) and the `wce.exe --capture` references (identical, or within one level in under 0.05 % of the pixels; `build/gates_base_perf`).

Scripted runs (`--fixed-step` / `--shot` / `--capture` / `--script`) ignore the real mouse and keys never auto-repeat, and an offscreen capture restarts the renderer's temporal state
(auto exposure, frame counter), so a capture is a function of the scene only.

## GPU

`libs/render/gpu_adapter` chooses the D3D11 adapter: `WCE_GPU=<part of the adapter name>`, otherwise the high-performance GPU, and the renderer logs `GPU: <name>` when it starts. Two GPUs do not round float math the same way,
so reference pixels only compare on one adapter (the gate scripts default `WCE_GPU` to `AMD Radeon`, see `docs/baseline.md`).
