# Reliable Terrain Save and Export

Complete-output staging, freshness checks and native scene preservation for the Terrain Editor, with the required shared publication implementation and tests included directly. No unmerged #51 branch is required; upstream Tile I/O is unchanged. This feature adds no Tile Editor Save/conversion, campaign-height preparation or persisted normal-baseline format. See the [developer handover](../terrain_editor_handover.md) and [Terrain roadmap](terrain_editor.md).

## Usage

1. Select the correct game, project directory and ordered kits in settings; open the map in Terrain. Project resources take precedence over kits/packs. Attila campaign render metadata retains its layered database lookup.
2. Edit a supported LF, layer, placement or scene field. **Save** writes the active project map folder: raw maps under `assembly_kit/raw_data/terrain/{battles,campaigns}/<map>`, built maps under `assembly_kit/working_data/terrain/{battles,campaigns}/<map>`.
3. **Save As** chooses a map-copy folder. It keeps the original active Save destination and history: dirty stays dirty, clean stays clean. A document restored from autosave also stays restored/unsaved after a copy; only successful Save to its owned project folder clears that status. The next Save writes the original project folder. A copy cannot take over a destination owned by another open document.
4. When disk files changed, choose **Overwrite** or **Cancel**. Cancel preserves files/model/history. Overwrite approves the observed disk change, but never bypasses native representability, complete resource identity or ownership checks. Unsupported changes still require correction/reopening.
5. **File → Export → Built files** generates supported loose native resources plus `terrain_<map>.pack` on a worker. The pack is built/staged before loose publication and published last. Export does not retarget Save or mark the document saved. Busy prevents concurrent Save/Export on that document.
6. Reopen from the project to check persistence. A successful Export is not game-runtime validation; use a disposable project and the appropriate game/BOB oracle for that check.

## Supported profiles

| Profile | Boundary |
|---|---|
| Attila raw/kit battle and campaign | Existing TIFF/cell/Terry authoring, project Save and native builders, retaining F1 metadata lookup. No new raw/native profile or all-campaign certification. |
| Rome II built/native battle | Existing bounded LF/CHMF/placement output and preservation-safe v7 BLM/deployment changes. Opaque tails/masks, key spelling and unrelated resources are retained; v6 placement reconstruction needs the correct database. |
| Other/native campaign | Preserve existing supported reader/writer behavior and opaque resources. No new native campaign-height/normal eligibility, native-Y semantics, prop controls or native Attila/Thrones certification. Held [#52](https://github.com/MrJox/warscape_community_editor/pull/52) is excluded. |

Native v9 placement integrity is the separate [#50](https://github.com/MrJox/warscape_community_editor/pull/50) contribution. This feature does not duplicate it or change placement policy; retain its provenance/paired-row guards when composing those contributions. This feature alone is not a replacement for that guard.

## Preservation and refusal

The writer creates the complete output plan before publication. All required files are staged beside their destinations, existing destination permissions applied and `sync_all` completed before any rename. Exact content is retained. Same-source/same-destination file outputs avoid content reads; distinct files and generated bytes are compared exactly. Identical read-only outputs may be retained; changed read-only targets fail. New files use creation defaults, not source permissions.

Validate the complete reader-visible key set: refuse traversal, reserved `.wce_tmp` components, case aliases, file/directory conflicts, decoded/opaque duplicates and cross-resource source associations. Unplanned destination files are preserved, including OS metadata, TEd additions and old deployment files. Their names must remain unambiguous alongside the planned outputs. Enumeration-time size/mtime observations survive loading; staging and each publication recheck freshness. Readers and observations follow regular-file links but skip dangling links and linked directories. This is neither an exclusive filesystem lock nor a content-hash watcher.

The native scene adapter captures original BLM/deployment bytes and source associations at load. Unchanged/reverted resources reuse original bytes. Edited candidates must preserve protected native layout and reopen to the intended values. Supported edits are bounded v7 catchment rectangle/position and deployment coordinate/orientation fields. Project Save refuses labels that cannot reopen, structural/type/unknown-field changes, unsupported name semantics, missing/ambiguous dependencies, non-finite/out-of-range or quantized-away values, and lossy replacement of protected native information. Native Export may omit scene-only labels; it does not save those labels to the project.

Overwrite never authorizes a refused native operation. Refusal preserves history/dirty state. Restore the unsupported change or source association and retry; never remove unknown data to make validation pass.

## Partial publication and recovery

Publication is **per-file stage-and-rename**, not a whole-directory transaction. A staging, permission or sync failure publishes no destination file. A later rename/freshness failure can leave earlier files replaced; the error reports successful publication count/paths and the document stays unsaved. Ordinary failure cleans remaining temporaries; reserved leftovers are excluded from loading and can be replaced on retry.

Keep the document open, release Busy/permission conflicts, review genuine external changes and retry normally. Own successful publications are recognized, avoiding false stale-source warnings. Terrain ordering publishes supporting resources first, then CHMF, preview/full LF and authoring metadata; the pack is last. A live cache retains certain original normal inputs if normals publish before their LF baseline, supporting the tested retry/independent-copy path without applying the same adjustment twice.

**Continuity limitation:** the cache is not persisted. Repeated native LF edits, close/reopen and process/power-failure recovery have no newly established normal-baseline continuity contract. No baseline sidecar/persistence implementation is included. Retain a known original generation when evaluating those cases. This limitation is separate from the tested single-operation, open-document retry behavior.

Copies retain the active folder's observations and outstanding overwrite choice, including outside edits to the original source. Choosing Overwrite for Save As approves that copy operation only; a later Save still asks about unreviewed outside changes to the original. A copy cannot approve an unrelated populated active folder. Repeat Save and Undo/Redo remain relative to the owned Save generation.

When Save is part of closing, opening a replacement or quitting, the existing unsaved-changes modal shows the disk-change choice in the same window. Overwrite saves that document and resumes the waiting action, asking about any later conflicts in turn. Cancel, Escape or the modal's X aborts the waiting action and keeps the remaining edits open. Documents already saved earlier in a multi-document action stay saved. Standalone Save All also resumes its remaining documents after each Overwrite.

Save All keeps its remaining-document cursor and earlier failures across each choice. A failed Overwrite still attempts later documents once. Scripted Save, Save All, close and replacement operations refuse unreviewed outside changes without leaving a pending modal; Discard clears an outstanding Save choice. Save As to the owned folder sends the same saved-source notification as plain Save.

Opening a map again rereads it through the normal Save/Discard replacement flow. An incoming document's destination is checked against other tools before the current document closes. An asynchronous map adoption keeps the destination it observed while waiting for a choice.

Export observes the selected map's loose subtree and its pack on the worker, so another project's files or autosaves under the output root do not abort it. Changes to that map, pack, or its source still stop publication. Save shares its initial capture across the prompt precheck, destination-name validation and staging, and captures each shared source/destination root once again before publication. Exact comparison happens once per Save output. Export generates the pack directly into publication staging and renames that completed file, without a second full pack copy. The [publication performance investigation](../investigations/publication_performance.md) gives the boundaries, measurements and opt-in benchmark.

If the graphics device is lost, the emergency Save attempts every modified, saveable document without waiting for an editor modal. It refuses unreviewed outside changes and continues with later documents. Any documents still unsaved receive recovery copies through the existing autosave system, even when periodic autosave is disabled; the native error dialog reports Save failures, recovery-copy results and the recovery folder. A device-loss exit preserves these copies for the next launch. This is best-effort recovery: a failed copy is reported, and successful ordinary Saves remain saved.

Restoring an autosave reads from its recovery copy. If the owned project folder already contains files, review the Overwrite/Cancel choice before saving there. Save As can write a separate copy while that choice remains pending; it neither approves the project overwrite nor clears the restored document's unsaved status.

## Focused tests

The [prompted and emergency Save contracts](../investigations/save_review_corrections.md) describe the maintainer-review corrections and their focused regression commands.

Use the [README](../../README.md#build), checked-out lockfile and existing caches. Synthetic tests need no game assets or environment setup. Native-preservation tests create a fresh per-case directory under the operating system's temporary directory. Optionally set `P004_SCRATCH` to choose a different writable disposable output parent; for example in PowerShell:

```powershell
$env:P004_SCRATCH = Join-Path ([System.IO.Path]::GetTempPath()) ('wce-save-tests-' + [guid]::NewGuid())
```

```text
cargo test --release --locked --offline -p wce_foundation -p wce_editor_core -p wce_terrain_io -p wce_terrain_editor -p wce_terrain_tool
cargo test --release --locked --offline -p wce_tile_io -p wce_tile_editor
cargo check --release --locked --offline -p wce_app -p wce_terrain_tool -p wce_terrain_editor -p wce_terrain_io -p wce_tile_io --all-targets
cargo clippy --release --locked --offline -p wce_terrain_editor -p wce_terrain_io -p wce_terrain_tool --all-features -- -D warnings
cargo fmt --all --check
```

Controls live in `wce_terrain_editor/src/{publication_tests,freshness_tests,save_validation}.rs`, `wce_terrain_editor/tests/{native_preservation,common/map_fixture}.rs`, `wce_terrain_tool/src/export.rs` and foundation publication tests. They cover upstream autosave/recovery composition, restored-document copy/failure/owned-Save state, staging/sync failure, permissions/retention, Busy/retry, copy/no-retarget, ownership, cancel/overwrite, aliases/complete keys, normal-input retry, opaque native retention, truthful Save/reopen and Undo/Redo.

For one existing licensed native witness, set `P004_D1_WITNESS_ROOT` to the prepared D1 root containing `rome2/terrain_battles_main_gaul/noop`, keep scratch separate, then run only:

```text
cargo test --release --locked --offline -p wce_terrain_editor --test native_preservation step_b_native_gaul_project_save_reopen_repeat -- --ignored --nocapture
```

Source resources stay read-only; output is scratch. Do not run all ignored corpus tests or bundle native files. Other platforms/profiles need their own checks. On Windows error 206, format/check every workspace member individually using the upstream configuration and record the fallback; do not claim the one-shot command passed.
